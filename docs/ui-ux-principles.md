# UI/UX and layout principles

This canonical guide applies when user-facing interfaces are introduced in
three-nn. It defines general principles without prescribing an application layout,
product features or a framework.

1. **Keep it simple.** Show necessary information and actions. Add controls,
   panels or steps only when they serve a concrete user need.
2. **Show results directly.** Use spacing, alignment, grouping and visual hierarchy
   to communicate structure. Remove redundant headings, repeated explanations,
   decorative status text and unnecessary panels.
3. **Make interactions intuitive and predictable.** Use familiar patterns,
   consistent appearance and behavior, and feedback that supports the task.

## Task hierarchy and discoverability

Prioritize the user's main task, content and result. Place controls near their
effects and group related controls together. Choose layout from actual tasks and
available space, considering obstruction and access to the content.

Keep frequent actions discoverable. Reveal advanced or contextual controls when
relevant without hiding necessary everyday actions merely to reduce visual density.

## Responsive layout and accessibility

Keep content readable and necessary actions reachable across screen sizes. Support
responsive layouts, keyboard access, logical focus order, visible focus, accessible
names, meaningful labels and readable contrast. Do not rely solely on hover, color
or visual cues to communicate actions or state. Preserve essential instructions
when simplifying presentation.

## Feedback and safeguards

Provide useful progress feedback, actionable errors and clear recovery paths when
needed. Avoid messages that merely decorate an already clear state. Preserve
necessary consent and destructive-action safeguards, including information users
need to understand consequences and act safely.
